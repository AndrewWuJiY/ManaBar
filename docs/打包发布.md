# 打包发布

本文只记录 ManaBar 当前工程的打包步骤。工程产物名为 `ManaBar.app`（显示名 ManaBar,工程内部也已统一为 ManaBar），版本号来自 Xcode build settings：`MARKETING_VERSION = 1.2.0`，`CURRENT_PROJECT_VERSION = 1`。

自 v1.1.0 起工程含两个 target：主 App `ManaBar` 与桌面小组件 `ManaBarWidgetExtension`（嵌入 `ManaBar.app/Contents/PlugIns/`）。

## 1. 打包前检查

1. 用完整 Xcode 打开 `ManaBar.xcodeproj`，不要只安装 Command Line Tools。
2. 在 Xcode 左侧选中项目 `ManaBar`，进入 target `ManaBar` 的 `Signing & Capabilities`。
3. `Team` 选择你的 Apple Developer 账号。
4. `Bundle Identifier` 保持 `com.andrewwujiy.manabar`。如果这个 id 已被占用，改成你自己的唯一 id，例如 `com.yourname.manabar`。
5. 顶部 scheme 选择 `ManaBar`（**不是** `ManaBarWidgetExtension`），运行目标选择 `Any Mac` 或本机 Mac。
6. 两个 target 的 `Signing & Capabilities` 都必须含 App Group `group.659P79368S.com.andrewwujiy.manabar`，否则小组件读不到额度、永远显示空态。换成自己的 Team 时，这个 group id 要同步改 `Shared/WidgetSharedState.swift` 引用的 `QuotaCache.appGroupID`（全项目唯一一处常量）。
7. 两个 target 的 `MARKETING_VERSION` 必须一致——Xcode 要求 app extension 的 `CFBundleShortVersionString` 与宿主 App 相同。`发布.command` 会在开头校验，不一致直接退出。

## 2. 只给自己用

1. Xcode 菜单选择 `Product` -> `Archive`。
2. Archive 完成后会打开 Organizer。
3. 选择刚生成的 archive，点击 `Distribute App`。
4. 选择 `Copy App`，导出 `ManaBar.app`。
5. 把 `ManaBar.app` 拖到 `/Applications` 后启动。

这种方式适合自己电脑使用。发给别人时，对方可能会遇到 Gatekeeper 的“无法验证开发者”提示。

## 3. 发给别人用

需要 Apple Developer 账号和 Developer ID 证书。

1. Xcode 菜单选择 `Product` -> `Archive`。
2. Organizer 中点击 `Distribute App`。
3. 选择 `Developer ID`。
4. 选择 `Upload` 让 Apple notarize。
5. notarization 成功后导出 `ManaBar.app`。
6. 压缩成 zip 后发布，例如：

```bash
ditto -c -k --keepParent ManaBar.app ManaBar.app.zip
```

## 4. 命令行归档

如果要用命令行，先确认 `xcodebuild` 指向完整 Xcode：

```bash
sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
```

归档：

```bash
xcodebuild archive \
  -project ManaBar.xcodeproj \
  -scheme ManaBar \
  -configuration Release \
  -archivePath build/ManaBar.xcarchive
```

Developer ID 导出：

```bash
xcodebuild -exportArchive \
  -archivePath build/ManaBar.xcarchive \
  -exportPath build/export \
  -exportOptionsPlist ExportOptions-DeveloperID.plist
```

导出成功后，app 在 `build/export/ManaBar.app`。

## 5. 常见问题

- 如果 `xcodebuild` 提示 active developer directory 是 Command Line Tools，说明没有切到完整 Xcode，按第 4 节先执行 `xcode-select`。
- 如果签名失败，先回到 Xcode 的 `Signing & Capabilities` 检查 Team 和 Bundle Identifier。
- 如果只是自己使用，不需要 notarization；如果发给别人长期使用，建议走 Developer ID + notarization。

## 6. 桌面小组件相关

- 小组件随主 App 一起构建和分发，无需单独导出。产物应含 `ManaBar.app/Contents/PlugIns/ManaBarWidgetExtension.appex`，缺了就是 Embed 阶段没配好。
- 用户侧需要 App 位于 `/Applications`，并在桌面右键「编辑小组件」中手动添加，App 内没有添加入口（系统小组件的添加/移除由系统管理）。
- **改了小组件代码后，桌面上已添加的小组件可能仍在跑旧二进制**，看起来像改动没生效。确认代码已更新却看不到变化时，把小组件删掉重新添加，强制系统重新加载 extension。
- 本项目当前用 Apple Development 证书签名、未走公证，用户首次启动仍需右键打开或 `xattr -d com.apple.quarantine`。若将来转 Developer ID + 公证，需重新验证 `Contents/PlugIns/` 下的 appex 是否一并通过。
